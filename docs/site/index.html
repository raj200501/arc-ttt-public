fencecheck

Is your evaluation scoring a correct answer as zero?

One file, standard library, no install. scan finds evaluation code that scores a correct-but-fenced answer as zero.

Python 3.9+. MIT.

The failure in one picture

When a language model returns a JSON object wrapped in a markdown code fence, code that calls json.loads on it gets a parse failure. If that failure becomes a score, a correct answer becomes a zero.

  • It is a mean, not thirty right answers. Once stripped, all 30 outputs are well-formed JSON, but in the words of CORRECTIONS.md (2026-08-25), “a 0.8958 mean cannot be thirty perfect extractions.”
  • It is family-specific. The tax has been measured on 2 of 5 families (Qwen2.5 at three sizes; Falcon3-1B). Given twenty examples of bare JSON the same checkpoints wrap nothing; given a bare field list they wrap everything. Results in VERDICT.md.

Try it

Copy the one file and point scan at your scoring code. scan reads your code and reports every place that parses model output as JSON without handling a fence and turns the failure into a zero or a silent skip. score reads your saved model outputs and tells you how many are valid JSON that your scorer would reject.

curl -sSLO https://raw.githubusercontent.com/raj200501/arc-ttt-public/main/tools/fencecheck.py
python3 fencecheck.py scan  path/to/your/repo
python3 fencecheck.py score path/to/predictions.jsonl

Commands from tools/README.md, with the tools/ prefix dropped for a copied file.

Exit status is 1 when something is found, so it drops into CI. Add --json for machine-readable output. To silence a deliberate one, put # fencecheck: ignore on the parse line or anywhere in the enclosing function.

See it find a real site

A markdown code fence makes OpenAI's evals steganography monitor report that it detected nothing: evals/elsuite/steganography/monitor.py:72. That prompt does say “do not generate any other text”, so a fenced answer disobeyed it. The finding is about which way the default falls when a model disobeys, not that the package is wrong.

The download is 44 MB. The full archive unpacks to about 0.7 GB, so this extracts only the .py files (about 3 MB):

curl -sSLO https://files.pythonhosted.org/packages/source/e/evals/evals-3.0.1.post1.tar.gz
python3 -c "import tarfile; t = tarfile.open('evals-3.0.1.post1.tar.gz'); t.extractall(members=[m for m in t if m.name.endswith('.py')])"
python3 fencecheck.py scan evals-3.0.1.post1    # monitor.py:72 is among the sites it reports

From tools/README.md. The expected output is banked in experiments/fence_census_amendment_2026-08-25.json.

In CI

One uses: line in a GitHub workflow, after the checkout:

name: fencecheck
on: [push, pull_request]
jobs:
  fencecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: raj200501/arc-ttt-public@main
        with:
          path: .   # optional; narrow it to your scoring code

Exactly as tools/README.md gives it. The action is action.yml.

It installs nothing from PyPI and pins no Python package, because the tool is standard library only. The job fails when the scan finds a site, through the tool's own exit status. @main follows this repository's main branch. Pin a full commit SHA if the gate must not change under you.

As a pre-commit hook, in .pre-commit-config.yaml:

repos:
  - repo: https://github.com/raj200501/arc-ttt-public
    rev: main
    hooks:
      - id: fencecheck

Exactly as tools/README.md gives it. The manifest is .pre-commit-hooks.yaml.

Then run pre-commit autoupdate once. pre-commit warns that main is a moving reference. This repository has no release tags, so autoupdate replaces main with the current commit SHA. The hook applies the same scan to every staged Python file, and a finding fails the commit.

What it does not catch

Expect most findings on a large codebase to be false alarms. The least flattering measurement, over seven actively maintained eval packages:

64candidate sites scan surfaced
1confirmed by hand adjudication
63rejected

Most of the rejected sites were telemetry and tracing code, file and config reads, or protocol transport (experiments/census_extension_live_2026-08-31.json). The detection rules have changed since that run (tools/README.md says how); a held-out census will measure the new rules.

The one confirmed instance is Braintrust autoevals JSONDiff, where the identical correct answer scores 1.0000 bare vs 0.2152 fenced, executed (same artifact).

So point path at your scoring code rather than the whole repository, read each finding, and mark the deliberate ones with # fencecheck: ignore. A finding is not a bug report. The defect is parsing without fence handling and then converting the failure into a score.

It reads one function at a time

If a helper parses strictly and raises its own exception, and the caller catches that exception and scores 0, the zero is one call away and scan does not report it. This repository's own scorer has exactly that shape, and scan reports nothing on that file. Read any parse helper that raises, and its callers, by hand. (tools/README.md)

How many real sites it misses has not been measured

Recall is unmeasured. It will not catch:

  • a file that does not end in .py (inside a directory);
  • a module that never uses one of its model-output words (completion, response, prediction, answer and the rest of MODEL_WORDS in the source);
  • a parse in a function that mentions fence handling anywhere, even for a different parse;
  • a failure turned into anything other than pass, continue, or a literal zero, False, None or empty container;
  • a parse whose failure reaches the caller, which is loud and left out on purpose.

How every number here is checked

Every number on this page is quoted from tools/README.md, README.md, VERDICT.md or CORRECTIONS.md, and links to the file that holds it.

tests/test_site_numbers.py reads this page, finds every token that contains a digit, and fails unless it appears both in the file it links to and in the document it is quoted from. The two CI snippets are checked character for character against tools/README.md. The test checks presence, not meaning: it cannot tell whether a number in a file is the one the sentence is about, and a small number appears in almost any file. The quoted sentence and the link are there so you can check that part by eye.

The numbers in the picture come from the stored model outputs. Rebuild the artifact with the standard library and compare it byte for byte:

python3 scripts/fence_rescore.py experiments/waybill_scale_rung_*.json --out /tmp/fence_rescore.json
cmp /tmp/fence_rescore.json experiments/fence_rescore.json && echo identical
