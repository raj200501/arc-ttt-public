# Addendum AD scoping survey: which public result sets could show a fence moving a published number

Written 2026-10-21 by a scoping agent. Read-only on the repo. Nothing was
filed, posted or sent. No model was run. Every HTTP fetch was small
(largest: 1,686,550 bytes, an HF API listing); two git size listings
pulled about 126 MB of blobs by accident, unread and deleted (section
7). Every number below was
printed by a command in this session; the command or URL is named.

## What was and was not looked at

- Looked at: dataset cards, file listings, column statistics, scorer
  source code at pinned commits, commit metadata (dates and titles), the
  header line and the model-name column of five published leaderboard
  tables, and **one** per-sample file (50 LiveBench answers from one
  model, fence tags only).
- Not looked at: any published per-task score value of the target task,
  any stored per-question score of the target task, any diff of a
  published table, or the content of any answer beyond where its fence
  opens. The `livebench/model_judgment` statistics response contains a
  `score` column; the printing script skipped it, and it holds no
  `tablejoin` rows anyway (see 2.3).
- One executed check ran LiveBench's historical scorer code on five
  **synthetic** answers to one synthetic ground truth (section 4). No
  LiveBench answer or ground truth went into it.

### 2.6 Feasibility check: one file, fence prevalence only

- File: datasets-server `/filter` page, `task='tablejoin' AND
  model_id='gpt-4o-2024-05-13'`, 28,125 bytes, sha256
  `2dc81677aa0f76acb1f20a1780866ad8bc7ca657a74131a224358c0498968015`,
  `num_rows_total` 50, 50 distinct question ids. Model chosen before any
  answer was read, as the release's reference model; it is one model and
  says nothing about the others.
- Script: `ad_scripts/fence_prevalence.py` (no parse, no scorer, no
  ground truth). Output banked at `ad_feas_livebench_gpt-4o-2024-05-13.json`.
- Result: **50 of 50 answers open with a fence, and all 50 fences are
  tagged `python`.** No ```` ```json ````, no bare fence, no fence after
  prose, no unfenced answer.
- Reading, as feasibility only: the data is reachable without an
  account; answers are per (model, question); fences are present; and in
  this one file every fence carries the one tag every scorer version
  handled. A flip needs a model that tagged ```` ```json ```` (any table)
  or left the fence bare (V1 tables). This is the strongest reason in
  this survey to predict a small count.

## 7. Limits of this survey

- Eleven result sets, chosen by what came to mind and what the brief
  named. Not a census; no rate over the ecosystem follows from it.
- "In force" for a LiveBench scorer version means committed to
  LiveBench's main branch. Uncommitted code on the maintainers' machines
  cannot be seen; the protocol's reproduction gate exists for that.
- Two of the three strongest candidates are gated behind an HF login.
- **A larger download than intended.** `git ls-tree -l` (sizes) on two
  blobless clones made git fetch the blobs: about 97 MB for WildBench
  (its `eval_results/`) and about 29 MB for microsoft/JARVIS. None of
  that content was opened, and both clones were deleted afterwards. The
  scratch download directory peaked at 140 MB, inside the brief's
  200 MB, and is 14 MB after deletion. Every other fetch was small.
- Code-reading verdicts outside section 4 were not executed.
- The repo was changing while this ran (commits `845ec5b`, `6f99c71`,
  `e4644bf` between 20:50 and 20:56 UTC). The `tools/README.md` sentence
  AD answers ("Whether that bias shows up in published work is a
  separate question that this tool does not answer.") was at lines 176
  to 177 at `e4644bf`.
